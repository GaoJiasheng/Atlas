# 2026-11-05：引擎首屏 JS 第一轮

## 范围与约束

本轮只处理首屏代码加载与打包，目标是不改变已有主题的显示结果和操作语义。修改限于 core 加载、PartNode、模拟运行时、UI 词表加载、构建配置和测试；没有改主题数据、HUD、取景、标注或 widget 文件，也没有改 package.json、锁文件、review-queue、next-batch。没有执行 git 写操作，没有打开或操作浏览器、桌面，没有运行 Chromium。浏览器验收交给 Claude。

词表沿用原来的两份 JSON，翻译和插值不变；SSR 仍同步取得完整词表，客户端按 common / space / time / math / index 分块；36 条仅由首页 SSR 使用的 index 文案不进入主题页。普通页面按需取语言；主题 HUD 本来就同时展示中英文，因此宿主在任何 hooks / 引擎挂载之前并行准备双语 common 和该引擎分组，避免 effect、事件与 store callback 抛出加载 Promise。两种语言都计入每一页的预算。引擎描述符和 geography / climatology URL 适配器按主题加载，原来的默认值、章节映射及 URL 函数保持不变。共享 URL 编解码器原样移至 core，模拟模块保留原路径的重导出，调用方仍取得同一组函数；地图和数学页不再因此导入 SpaceScene 模拟模块。

词汇表卡片只在打开时加载，其数据读取保持原有行为。液体填充的几何与缓动函数原样移到数据驱动的懒加载边界：目前只有 sample-matter、states-of-matter 使用。模拟时钟文案仍使用原来的富文本显示与朗读函数，仅 light-and-shadows、sample-light、sample-orbit、sun-earth-moon 的 `format: time` 数据需要该边界。宿主在 rebase 数据、挂载引擎之前等待模拟工具、当前求解器、填充及时钟运行时，避免第一帧缺失或过早报告 ready。模拟工具的浏览器 facade 仅在存在 sim 时加载原实现；没有 sim 的主题仍同步取得材质高亮、方向插值与普通读数标签所需的小函数。SSR / 内容校验保留原同步 API。

以上边界由已有语言、engine、fill、format 数据或打开词汇表的操作决定，没有新增产品开关。新增外层错误边界复用原有中英文场景失败文案，词表本身加载失败时也能显示。

构建使用锁定工具链已有的 Terser，保留安全默认选项，压缩两遍，不开启 unsafe 或属性名混淆。Vite / Vitest 缓存放在工作树 `.astro` 内，避免写共享 node_modules。Vitest 的 Html 深路径显式解析到现有文件；几何测试改为单 worker，运行器超时设为 120 秒；没有减少断言、跳过用例或缩减参数覆盖。恢复前已从 5 秒调整到 15 秒，但共享机器负载持续约 160–450，串行后原有 toad 正确性用例仍耗时 49 秒，新增完整参数对照也超过 15 秒，因此需要为正确性测试留足运行时间。这不是放宽产品性能断言；JS 字节上限仍严格执行 469 / 442 KB。最终按此默认配置完整重跑。

## 过程测量与统计修正

单位均为 KB gz，1 KB = 1024 B，逐文件 gzip 后求和。原始实际构建基线为 aircon 446.52、sample-space 508.70、ancient-civilisations 480.17。

2026-11-05 的中间表把按语言拆包后的当前语言作为唯一词表根，遗漏了 HUD 双语标题和标注真正会下载的另一份词表。因此旧中间表已作废，不将它当成有效性能收益。2026-11-09 恢复时曾得到 aircon EN 401.49 / ZH 402.23、sample-space EN 463.06 / ZH 463.80、普通地图 EN 436.54 / ZH 437.11；这些数值同样遗漏另一语言，不能作为达标结论。已修正脚本、闭包断言和文档。

本轮保留的拆分依次是：UI 按引擎分组；宿主按 engine 加载描述符与 URL 适配器；词汇表渲染器按打开动作加载；fill 与 time 格式按数据加载；bind / carrier / replay / text / table 的模拟工具按 sim 数据加载。首帧需要的动态入口全部回加预算，不能用只出现宿主或加载提示来规避计量。

曾试验将 three 指向源码入口，以及将命名导入解析到源码模块。aircon 收益不足 1 KB，而 sample-space 增加约 9 KB、地图增加约 3 KB；两项实验及其代码、配置均已撤回。现有 drei / three extras 已有数据驱动的懒加载，本轮没有修改不属于本任务的舞台、几何或 HUD 源文件。

进一步合包曾把 three / R3F 与应用一起归包，构建明确出现 RoundedBoxGeometry 的跨 chunk 循环；该方案已撤回。保留的配置只合并 SpaceScene 已有的静态应用依赖，保持 vendor 独立，描述符保留小入口，动态 GLTF、body 与模拟模块不归入公共包。构建测试检查描述符静态闭包不含舞台或 three / R3F，防止延后 data.json 请求。

## 单元测试与计量口径

- 词表资源只取请求的语言、合并并发请求、复用缓存、传播失败并支持显式重试。
- 两种语言的全部 UI 键和占位符逐键核对；分组可无损重组为原词表，失败文案与原文一致。
- 双语分组在挂载前并行预备，之后从微任务 / effect / 事件路径读取不会再悬挂。四个异步引擎入口与原同步描述符完全相同；地图三种视图身份稳定，月度 / 地理 URL 适配器仍是原函数。
- 词汇表数据抽取与原实现一致，并保持原数组引用。
- 液体和时钟依赖只在明确的数据条件下准备；填充仍使用同一组几何、容量与缓动函数。时钟覆盖双语、舍入、跨午夜、短格式、朗读及非有限值回退。
- 使用真实 Vite / Rollup 的内存构建，检查数学富文本及模拟工具仍在各自动态边界之后；另将浏览器配置产物交给 Node 原生 import 执行，覆盖 table / magnet / time 的循环依赖和同步回调，不调用浏览器。
- 预算对 EN / ZH 分别测量，显式计入当前语言、引擎描述符、所需 UI 分组、模拟求解器及数据决定的运行时和舞台功能。闭包仍递归统计静态 imports 并去重，不因改成动态 import 就漏计首帧必需代码。
- 构建预算测试检查双语 common 及所选引擎分组均进入闭包，无关引擎和无关词表分组不进入闭包；有 sim 才计入工具运行时，无 sim 的闭包不得含重型模拟实现。地图库不进入其他引擎，three / R3F 不进入地图或数学引擎。四个时钟主题确实需要共享富文本里的 fraction / decimal / value / words 四个纯格式函数，断言只对这四个必要函数开放精确例外，仍禁止引入 MathScene 舞台和 UI；这些字节完整计入预算。

## DECISIONS FOR GAVIN

1. **下一轮的授权范围**：本轮仍有 56 个 SpaceScene 主题高于 400 KB，最大 466.73 KB。是否另开一轮，覆盖目前不归本任务所有的 SpaceScene View、SceneRoot、geometry 及它们的依赖边界，继续按主题数据拆分？不要通过提高 ratchet 或漏计首帧必需模块来接受超额。docs/02 的 300 KB 长期目标保持不变。
2. **词汇表首次打开的验收**：卡片现在首次打开才取渲染器，保留原数据、样式与操作。请在 Claude 的真实浏览器冷缓存验收后判断首次打开的响应是否可接受；若需要后台预取，应另明确预取时机及计量口径。
   - **Claude 验收（2026-11-09）**：headless Chromium（Metal GPU）冷缓存实测，首次打开从 6–13 ms 变成约 310 ms（CPU 4× 降速约 330 ms）。分块本身只要 2–7 ms，慢在 React 19 对 Suspense 揭示的约 300 ms 节流。已改成：引擎视图挂载后在空闲时（无 `requestIdleCallback` 的 iOS WebKit 用 0.5 s 定时）预取卡片，首次点击直接渲染；卡片类型只选一次，避免已打开的卡片被重挂载。预取发生在首帧之后，不计入首帧预算。
