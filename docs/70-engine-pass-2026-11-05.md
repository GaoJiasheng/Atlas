## 2026-11-05：引擎首屏 JS 第一轮

### 范围与约束

本轮只处理首屏代码加载与打包，目标是不改变已有主题的显示结果和操作语义。修改限于 core 加载、PartNode、模拟运行时、UI 词表加载、构建配置和测试；没有改主题数据、HUD、取景、标注或 widget 文件，也没有改 package.json、锁文件、review-queue、next-batch。没有执行 git 写操作，没有打开或操作浏览器、桌面，没有运行 Chromium。浏览器验收交给 Claude。

词表沿用原来的两份 JSON，翻译和插值不变；SSR 仍同步取得完整词表，客户端按 common / space / time / math / index 分块；36 条仅由首页 SSR 使用的 index 文案不进入主题页。普通页面按需取语言；主题 HUD 本来就同时展示中英文，因此宿主在任何 hooks / 引擎挂载之前并行准备双语 common 和该引擎分组，避免 effect、事件与 store callback 抛出加载 Promise。两种语言都计入每一页的预算。引擎描述符和 geography / climatology URL 适配器按主题加载，原来的默认值、章节映射及 URL 函数保持不变。共享 URL 编解码器原样移至 core，模拟模块保留原路径的重导出，调用方仍取得同一组函数；地图和数学页不再因此导入 SpaceScene 模拟模块。

词汇表卡片只在打开时加载，其数据读取保持原有行为。液体填充的几何与缓动函数原样移到数据驱动的懒加载边界：目前只有 sample-matter、states-of-matter 使用。模拟时钟文案仍使用原来的富文本显示与朗读函数，仅 light-and-shadows、sample-light、sample-orbit、sun-earth-moon 的 `format: time` 数据需要该边界。宿主在 rebase 数据、挂载引擎之前等待模拟工具、当前求解器、填充及时钟运行时，避免第一帧缺失或过早报告 ready。模拟工具的浏览器 facade 仅在存在 sim 时加载原实现；没有 sim 的主题仍同步取得材质高亮、方向插值与普通读数标签所需的小函数。SSR / 内容校验保留原同步 API。

以上边界由已有语言、engine、fill、format 数据或打开词汇表的操作决定，没有新增产品开关。新增外层错误边界复用原有中英文场景失败文案，词表本身加载失败时也能显示。

构建使用锁定工具链已有的 Terser，保留安全默认选项，压缩两遍，不开启 unsafe 或属性名混淆。Vite / Vitest 缓存放在工作树 `.astro` 内，避免写共享 node_modules。Vitest 的 Html 深路径显式解析到现有文件；几何测试改为单 worker，运行器超时设为 120 秒；没有减少断言、跳过用例或缩减参数覆盖。恢复前已从 5 秒调整到 15 秒，但共享机器负载持续约 160–450，串行后原有 toad 正确性用例仍耗时 49 秒，新增完整参数对照也超过 15 秒，因此需要为正确性测试留足运行时间。这不是放宽产品性能断言；JS 字节上限仍严格执行 469 / 442 KB。最终按此默认配置完整重跑。

## 2026-11-05 · SpaceScene 引擎首轮：HUD、取景与标注

### 范围与约束

按 `CLAUDE.md`、架构文档、开发指南及技术图版 §2 实施。仅修改 SpaceScene 引擎、共用 HUD 空区数学、测试和 steam-engine 的 Newcomen 预设；没有修改其他主题数据、SceneHost、国际化加载、依赖声明或锁文件。未操作 Git 写入、用户浏览器或桌面；未运行 Chromium。浏览器验收由 Claude 后续执行。

### 已完成

#### 1. hudFrame 稳定取景

根因是求解器的分支顺序，而非相机作者数据：第一个空区只要可行就提前返回；它在边界略变后不可行时，才搜索其他空区。以实际 coral-reef GLB 的章 01 镜头及平板 HUD 矩形复现，触手尖端边界 ±0.03 会使相机到 target 的距离从约 8.19 跳到 15.41。远处、原本不在画面的模块也参与 HUD 避让，进一步放大可行性边界。另发现相机此前会在模型绘制就绪前用临时边界取景。

修复：

- 比较各个 HUD 空区的安全解，优先最小后退距离；不再让第一个可行空区独占选择。
- 紧贴边界的解没有足够平移余量时，搜索有限的额外距离：没有主对象尺寸下限时最多增加 50%；有下限时以该下限允许的距离为界。
- 允许保留上一帧仍安全且距离不比最优解远 6% 以上的镜头；重查主体入框和 HUD 避让；调用者在作者镜头变化（包括换章／换预设）时重置历史。
- HUD 极端拥挤且完全无安全解时，退回按整个视口拟合主体的镜头，不再退回未拟合的原始镜头，也不沿趋近零宽的 HUD 缝隙无限后拉。用 20 px、0.03 px、0 px 缝隙验证回退一致。此时不能保证 HUD 完全不遮挡；正常布局继续优先安全解。
- 等已有 scene／model／overlays 的绘制 fence 和 HUD 实测完成再处理取景；等待期间不报告 HUD 已安置。GPU fence 完成后唤醒按需渲染循环，使等待中的相机能继续。
- 输入边界与布局未变时复用结果，避免每帧重复求解。

改动仅作用于现有 `views.hudFrame` opt-in；未给其他主题添加此配置。

#### 2. inset 与标签／引线

`views.insets` 使用与可见虚线框相同的实时投影和 padding，传入标签布局。标签和两段引线必须始终处于边框同一侧：外部标签不能穿窗，内部锚点只能在窗内安置标签；窗内标签也避开 inset 零件的投影框。滑动路径不安全时直接落到合法位置；无合法位置时立即隐藏，避免淡出中的旧引线穿框。

约束提供器位于已有按数据懒加载的 `InsetFrames` 中，通用布局只接收约束回调；未声明 inset 的主题不下载专用算法。现有首屏预算工具会把声明 inset 的主题所需模块完整计入。提供器每帧读取与虚线框相同的 bridge 投影与舞台尺寸，避免 resize 时两套尺寸产生偏差。

空间不足时允许省略标签；阅读面板的对象详情和章节索引仍可访问。1024×768 的 hair-cell 窗口约宽 200 px，完整标签和水平引线未必放得下。没有擅自移动、放大主题模型或虚线框。

#### 3. 数据驱动的预设可见性

相机预设增加可选 `layers`，含义是选择该预设时必须显示的组；与当前图层取并集，不关闭其他图层。对这些组的成员，清除章节 hide／ghost，并解除 solo；其他零件的隐藏保持。`view` 继续由预设显式声明。schema 校验组引用；没有 `layers` 的预设沿用原规则。

steam-engine 的 `newcomen-view` 声明 `layers: [teaching]` 与 `view: assembled`。一些章节除了关闭图层，还明确 hide 了 `nc-*`，因此仅开图层不足；现在在这些章节及 isolate／solo 状态下选择预设也能看到模块。VIEW 按钮、数字键 4、正文 FlyTo 仍经同一 HUD action／scene store；拍中字符串 camera 仍只引用镜头，不隐式改拍的图层。
