# FACT DISCIPLINE — 真实主体的事实纪律

主体是真实产品 / 真实机器时，页面上的每个技术数字都会被当成厂商数据。三个项目里最容易出事的地方就在这里。

## 1. 四类信息，视觉上可区分

| 标签 | 含义 | 例 |
|---|---|---|
| `FACT` | 厂商当前公开页面明确写出的参数 | 2 MW @ 3°C ATD |
| `REF.`（或具名，如 `DESCHUTES REF.`） | 行业规范 / 参考设计 / 同系列资料，不等于本产品 | 规范里的 BOM、压力范围 |
| `RECONSTRUCTION` / `DESIGN STUDY` | 根据照片推断的几何、看不到的内部走管 | 内部歧管走向 |
| `SIMULATED` | 运行时动态值 | 实时流量、温度 |

HUD 中做成小标签芯片（1 px 框 + 小号大写 + 中文），面板每行右侧一个。规格表的值后面也带芯片。

## 2. 写 `docs/FACTS.md`（或简报里的事实表）

- 只记录可以安全视为公开事实的内容，每条带来源 URL。
- 来源之间数字不同时，不要偷偷选一个当唯一真值；在报告中列出差异。
- 尺寸只给数字没给轴向时，建模可按 W×D×H 映射，但 HUD 写 `MODEL DIMENSION MAPPING` 或在报告说明映射依据。
- 事实优先级：厂商当前产品页 > 官方市场 / 合作方页面 > 行业规范 > 照片推断 > 展示性设计。

## 3. 禁止伪造

没有来源时不要出现：精确功率、传感器型号、部件数量（作为官方事实）、管径、效率、可带负载数量、控制时序。现场展品不要宣称一定是某个具体型号版本，用 `REFERENCE STUDY`。

## 4. 模拟值

- 明确写 `SIMULATED OPERATING POINT`。
- 内部自洽：例如温差、流量、热负荷满足能量平衡（2 MW、500 GPM PG25 → ΔT ≈ 16 K）。
- 允许轻微抖动表达"实时"，但不要给出看起来像实测的高精度。

## 5. 声明

左上或底部加一行双语声明：`Independent visualization study · not an official {Brand} publication` / `独立可视化研究 · 非 {品牌} 官方发布`。

## 6. 参考图与 decal

- 参考图默认只用于开发对照，不嵌入成品（版权归原权利人）。
- 用户允许时，logo、面板屏幕、铭牌可从官方照片裁切做 decal：透视校正 + 去光照（拉平明暗），贴在对应几何上。
- 不锈钢管、黑框架、电机、泵、换热器大表面不要用照片当 baseColor（照片自带光照和透视，会双重光照）；用照片校准颜色 / roughness，再用程序化 PBR 重建。

## 7. 抓取资料

- 写 `scripts/fetch_refs.sh` 下载官方图时：curl 带 UA、重试、`.part` 临时文件；某个源失败（如 Cloudflare 403）打印 WARN 继续，不中断开发。
- 抓不到的网页可以用真实浏览器打开后另存。
- 在报告中列出缺失的资料。

## 8. 自动事实审计

收尾时扫描页面里所有带数字的 UI 字符串（含 hover 说明），每个要么在事实表里有来源，要么带 `SIMULATED` / `REF.` 标签。目标：0 条未标注的非事实数字。

## 9. 照片配准（提高 silhouette 准确度）

- 为 FRONT / REAR-3Q / REAR 等官方视角建固定 FOV 的 match 相机。
- 屏幕空间半透明 overlay（0–100% 滑块）叠加对应照片。
- 先配主框架，再大件，再管路，最后小件。
- 参考图是透明背景 PNG 时，可以渲染模型剪影与照片 alpha 计算 IoU，自动搜索相机参数后再人工修几何；导出 diff 图存到 `shots/register-*-diff.png`。
