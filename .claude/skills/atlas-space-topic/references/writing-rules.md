# 写作规则（科学 / 生物主题）

范本：空调第 03、04 章（`src/content/topics/aircon/chapters/`）、`parts.json` 的零件说明、`sources.json` 的 S1 与 S29。通用规则（双语、`<More>`、`<Term>`、来源冲突写区间）与 skill `atlas-history-topic` 的 `writing-rules.md` 相同，这里只写拆解主题自己的部分。

## 口吻

- 读者是一般读者（含小学生和家长）。**通俗不幼稚**：短句、具体、先现象后原理；第一次出现的概念当场用一句话解释，或包 `<Term>`。
- 科学语域：说"热从较热的物体传到较冷的物体"，不说"冷气跑进来"；说"冷媒在蒸发器里沸腾"，不说"冷媒变成冷气"。用词对齐 MOE 小学科学（热的传递、物态变化、蒸发与沸腾、凝结、热的良导体 / 不良导体；生物：系统、器官、功能、适应、生命周期），专业词进名词表。
- **不拟人**（"压缩机很累""蚂蚱想逃跑"）、不喊"小朋友们"、不用感叹号和问句标题、不写"神奇的""令人惊叹的"。生物：不写目的论（"为了跳得远，它进化出了…"→"后腿里粗大的肌肉让它能跳起来"：写结构和作用，不写目的；跳多远这类数字带来源）。
- 不推荐产品、不比较品牌；能效、用电、安全只讲原理和官方建议。安全如实写（R32 微燃、要持证人员安装），不渲染危险也不回避。生物的捕食、寄生、解剖如实、克制。
- 每章：正文 EN 200–300 词 / ZH 350–500 字，3–5 段，先讲舞台上看到什么，再讲为什么 → 细看 `<More>` 2–4 块。默认不做测验。

## 数字：TYPICAL / DESIGN / SIM

| 类 | 是什么 | 写在哪里 | 来源 |
|---|---|---|---|
| TYPICAL | 公开来源给出的典型范围（厂商规格当"典型"引，不点名） | 正文、细看、零件 detail | 各自的 S# |
| DESIGN | 本设计研究取的值，落在 TYPICAL 内 | 规格行（`tag: design`）、细看 | 设计研究来源（空调 S29，脚手架 S1） |
| SIM | 模拟运行点的结果，满足能量 / 质量守恒 | STATE 读数（SIM 芯片）、细看、字幕 | 同上，算式在相关来源的 `note` |

- **设计研究来源是自描述的**：`text` 写"本主题的 Atlas 设计研究（通用对象，不对应任何品牌 / 型号 / 标本）。设计值：…。模拟运行点：输入…。结果：…"；`note` 写"不是实测值。设计值落在 S#–S# 的范围内（例外：…，原因）；输入数据与算法见 S#、S#"。每个用到的物性数据来源的 `note` 里写清算式（空调 S1：流量 = 2.6 kW ÷ 230 kJ/kg ≈ 0.011 kg/s）。
- 正文里每个数量包 `<Num s="S#">`（只包数字和单位，不包年份、序号）：`at about <Num s="S1">3.0 MPa</Num>`；设计值、模拟值也照样包，引设计研究来源。正文写取整加"约 / about"，精确值放细看。
- 模拟值在句子里写明"在这个模拟运行点 / at this simulated operating point / in this simulation"；**字幕和零件 detail 里的模拟数字不加 `<Num>`**（字幕是纯文本、detail 用 `[S#]`），但句子里同样写明"在这个模拟里"。
- 规格行、STATE、正文、字幕、detail 里同一个量必须同一个值（空调发布前修过一次：正文 300 kJ/kg vs 细看 230 kJ/kg）。发布前逐个对。
- 视觉上的放慢、放宽要说：转速"画面里放慢了几十倍"，鳍片"模型把间距画宽了，真实约 1.4 mm"。
- 来源冲突并列，两端各用自己的来源（`<Num s="S13">24 %</Num> … <Num s="S14">37 %</Num>`），`note` 里写为什么不同。只读到搜索摘要的来源在 `note` 写明，列入 spec 已知差距；挡爬虫的页面用浏览器读原文后再引。

## 零件 summary / detail

- `summary`（≤ 60 字符，也是引线标注的一行说明）：**它做什么**，动词开头，一句话。"Squeezes the gas so it gets hot; drives the loop." / "把气体压缩得很热，推动整个回路。"
- `detail`（2–3 段，空行分段，数字带 `[S#]`）：
  1. **怎样做到**：结构 + 原理（"一个密封钢罐，里面是电机和转子泵；气体从侧面进、顶部出"）。
  2. **典型数字**：TYPICAL 范围和本设计的值，写明哪个是模拟（"约 85–90 °C（模拟运行点）[S1]，低于厂商给 R32 定的 115 °C 上限 [S26]"）。模型和真实的差别也写在这里。
  3. **坏了 / 脏了会怎样**：一句后果（"鳍片被灰尘堵住，过风就少，同样的电换来的制冷量也少"）。生物：受伤、病变或缺少时会怎样，或与相近物种的差别。
- context 零件的 `detail` 写它为什么在场景里、哪里是示意。

## 章节与细看

- 第 01 章：整体是什么、由哪几大部分组成、各在哪里、多大（规格行的设计值在这里第一次出现）。之后每章一个过程或一个子系统，最后一章讲使用、维护或与生活的联系。
- 细看的典型四类：**模拟运行点的数字**（算式、写明 SIM）/ **模型和真实的差别**（示意布局、放宽的间距、省略的件）/ **常见误解**（"空调制造冷气"、"细管里是热液体"）/ **与新加坡和生活的联系**（官方建议、法规，数字带来源）。
- `<FlyTo preset>` 放在讲到某个部件的那段末尾，文字是动作（"Start at the compressor / 从压缩机看起"）。
- `<Term>`：名词表 12–16 个**正文里真正用到**的词，每个只包全主题第一次出现处，EN、ZH 各一处。

## 节拍字幕（`state.beats`）

- 一拍 = 模型上一个**可见的变化**：镜头移到一个部件、一组零件被移开、视图切到 X-RAY、开始运转、拆开。不是正文段落的缩写。
- 每章 3–5 拍；第一拍是本章的全景，后面沿过程的顺序走（冷媒：压缩 → 冷凝 → 节流 → 蒸发）。
- 字幕描述**这一拍模型上显示什么**，再加一个数字或一个原因：`In the simulated condenser the hot gas gives its heat to the 33 °C outdoor air. At 3.0 megapascals it condenses at about 48 °C, so it turns into liquid.` 一到两句，EN ≤ 45 词；会被语音朗读：不用括号、缩写和符号（写 "megapascals" 不写 "MPa"，中文写"兆帕"；"°C" 可以）。
- 第一次出现颜色或疏密编码的那一拍说一次图例（"橙色是热，灰色接近室温，青灰色是冷。点密是液体，点疏是气体"）。
- 这拍 `labels` 里的每个零件都要在画面里有引线（≤ 6）；`pnpm shoot <slug> --beats` 列出漏标的，多半是镜头没框住或被外壳挡住。

### 节拍的标注与镜头（蝗虫主题 B 步实测的引擎行为）

- **拍里的 `labels` ≤ 6、全部要在画面里**。标不出来先查原因，再用镜头或 state 解决，不要删掉该标的 id：
  - 被 `ghost` 的零件不标注。外骨骼整组淡显时，要标的口器、鼓膜、产卵瓣必须从 `ghost` 里排除：`ghost` 可以写零件 id 列表（组里除它以外的零件逐个列出）。
  - 引线锚点是零件包围盒的中心。中心落在被剖切掉的一侧就没有标注：成对零件的数据侧（+Z）在矢状剖切里被切掉，写 `<id>-r` 标另一侧；中心恰好在剖切面上的零件（马氏管、中线上的器官）会被剖切面"夹掉"，把剖切面 `offset` 放宽 0.02（0.5 mm）；横切面落在零件中心之前时（嗉囊、飞行肌），换成中心在切面之后的零件，或换切面位置。
  - 锚点被别的零件挡住（侧视腹背板后面的股节、翅）：这拍 `hide` 掉遮挡件，或把镜头抬到 50° 以上俯视；X-RAY 下标注不判遮挡。
  - 章 `state.labels`（不是拍的）在非演示模式下受**镜头距离限量**（`labelBudget`：距离 / 模型半径 < 1.6 时 3 个，到 3.4 时 10 个），近景章只写 3 个；拍的 `labels` 不受限（演示最多 6 个）。
- 近景和剖面里会有无关的长件穿过画面（触角、后胫节）：这拍 `hide` 掉，字幕写明"这里藏起来了"，不要靠镜头躲。
- 一拍里不想让某系统抢画面（神经章里的飞行肌）：这拍 `layers` 不开它，或 `hide` 该零件；`ghost` 是"淡显"，不是"关"。
- 标本盘类排列（卵荚、若虫）从正前方看会互相遮挡：镜头抬高俯视，并 `hide` 掉遮挡的 context 件（土壤剖面）。

### 来源可达性（蝗虫主题 T 步实测）

- **能读全文**：PMC / Europe PMC 的开放获取论文；archive.org 的公有领域旧书（Snodgrass 1930、1935，Smithsonian Misc. Coll.）；Commons；政府与博物馆页面（FAO Locust Watch、NParks、气象局、LKCNHM 数字自然档案与 PDF、Orthoptera Species File）；开放获取 PDF（如 Indochina Entomologist 2025）。
- **只读到摘要**：1970 年代前后的 JEB / Bulletin of Entomological Research 论文（出版社页面、Europe PMC、OpenAlex 的摘要）；Google Books 只有片段。这类来源的 `note` 写"Abstract read"，只引摘要里写着的数字，不补数字。
- **拒绝自动访问**：Singapore Statutes Online（改读 FAOLEX 的合并文本并在 `note` 写明）；iNaturalist 网页（用 API，写取数日期与筛选条件）。
- **数字只在图里**：读图并在 `note` 写"读自图 N 的柱状图，数值为估读"（S25 的心率）。
- 近缘种的数据在正文、字幕、细看都点名物种；本种没有的数（体重、跳跃、气门模式）宁可不写，也不要借了不说。

### 写作检查（发布前逐条）

- `grep -rnE "draft|placeholder|TODO|T1|T2" src/content/topics/<slug>` 为空。
- 字幕里的数字：`grep -nE '[0-9]' chapters/*.mdx` 在 `state.beats` 范围内逐条对照正文的 `<Num>`；借自近缘种的写明物种；模拟值写"在这个模拟里"。
- 字幕与正文同一个量同一个值（龄数、气门数、毫秒数）。
- 无品牌、无拟人、无目的论、无"小朋友"、无感叹号。

## 双语

- 中文独立成文，不是翻译腔；数字、单位与英文一致，句子不必一一对应。
- 数字与单位：EN `0.80 kg`、`2,600 W`、`48 °C`；ZH `0.80 kg`、`约 48℃`、`每分钟 3,600 转`；中文数字与汉字之间留空格（`约 1.0 兆帕`）。
- 部件名用行业通行译名（冷媒 / 制冷剂、蒸发器、膨胀阀）；生物用中国大陆通行学名和俗名，第一次出现附学名（斜体拉丁名只在细看里）。

## Gavin 审

- spec 的决策表、事实表、章节表；第一章样章做完后的整体观感（结构像不像真物、读法清不清楚）。
- 安全、健康、伦理相关的段落（冷媒可燃性、电费与用电建议、动物的捕食与解剖细节）。
- 示意布局和与真实的差别是否说清楚。
