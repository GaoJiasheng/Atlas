## 1. 课纲对照
- 1.1 课纲原文表：级、条目编号、英文原文（逐字）、页码；核对要点（常见二手说法的纠正）。
- 1.2 级别与步数：主体 / 地基 / 桥；步数（分数是 12 步 + 练习 + 背景章）；时间预算（讲解每拍 ~20 s、小测每题 ~40 s、练习每题 ~40 s）。
- 1.3 步表：`# · 步 id · EN · ZH · 课纲 · 模型 · 拍数 · 题库题型`。

## 2. 逐步设计（每步一节）
- 概念一句话（EN / ZH）。
- **讲解节拍草图**：每拍一行 `[模型 · 份 · 给定 / 加上 / 拿走 · 叠加] → 算式 · 字幕要点 · 过渡（cut / fold / split / merge / convert / shade / cross / place / morph）`。3–5 拍，第一拍是"你已经知道的"，最后一拍是本步的结论或一个应用（文字题配模型图）。
- **常见误解**（§2.2 的 code）与正文里怎么讲它。
- **题库计划**：8–10 道的题型分布（例：4 道 input、3 道 shade、2 道 choose），每道针对哪个误解；本步的数字约束。
- 要点（keyFacts）2–4 条一句话。

## 2.2 误解目录
`code · 误解 · 典型表现 · 反馈要点（样例口吻）· 来源`。诊断只认题目声明过的 code（`feedback.wrong`、`choose` 的错选项）。新 code 要先加进 `schema.ts MISCONCEPTIONS` 和 `lib/check.ts` 的诊断规则，并补单测。

## 3. 练习章
6–10 道固定题，至少 5 种题型；每题 `revisit` 指向教它的步；每题一次检查、一个提示；总结页一句话 + 表格 + "再做一次"。

## 4. 引擎缺口
本主题需要而 MathScene 没有的东西（新模型种类、新任务类型、新误解诊断、新过渡），每条写清 schema、舞台、托盘、检查、单测、docs/06 改哪里。没有就写"无"。

## 5. 写作规则（照 docs/15 §5 + 本 skill `writing-rules.md`）
5.1 口吻样例；5.2 术语表（MOE 英文 · 中文 · 备注）；5.3 数字与情境。
